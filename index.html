CHAPTER 09 / HEAP

堆内存怎样分配？

一个 128 字节的堆按块管理。申请时采用首次适配，释放时合并相邻空闲块；三维色块表示同一份堆状态。

每个块有 8 字节头部，数据区按 8 字节对齐。试着依次申请 16、24 和 32 字节。

选择已经分配的块并释放。相邻空闲块会合并；不相邻时仍可能出现碎片。


 
空闲空间总量足够，但没有任何一块足够大时，申请能成功吗？

 
在 256 字节 arena 中实现 my_malloc 和 my_free：返回的地址须按 8 字节对齐；释放中间块后，用首次适配复用它；相邻空闲块要能够合并。检查器会编译你的 C 代码并测试范围、重叠、复用、数据保持、空间不足和合并。
原创配套作业，有限测试并不能证明完整正确。检查器在 wasm32-wasi 运行，和上方堆模型使用各自的数据。

 
这是首次适配堆的教学模型，块头和合并规则是本实验的设定；不是官方 Malloc Lab 的 C 分配器和评分系统。

 
绿色表示仍在使用的有效载荷，深色表示未观测区域；无法从调用记录判断块头、空闲块或合并情况。三维视图最多显示前 7 个载荷，完整列表见下方。

CHAPTER 08 / PROCESS CONTROL
fork 之后发生什么？

 
父进程通过 fork 创建子进程。两个进程各有自己的变量副本，父进程还需要回收退出的子进程。

 
初始时父进程的 x = 1。fork 后，父进程得到子进程号，子进程得到 0。

 
子进程将自己的 x 加 1，父进程的 x 会变成 2 吗？

 
父进程可以先等待，也可以在子进程退出后调用 wait。试试两种顺序。

 
这是 fork、退出和 wait 的教学模型，变量是简化的进程私有状态，不会创建真实系统进程。

两个描述符，几个位置？

 
进程通过文件描述符访问打开的文件。描述符可以指向同一条打开记录，也可以指向两条独立记录；读取位置属于打开记录。

CHAPTER 12 / CONCURRENCY
两个线程，一份数据

 
两个线程各执行一次 counter++。选择每一步由哪个线程运行，观察两个核心和共享变量的变化。

 
计数器从 0 开始。两个线程各加 1；如果它们的操作交错，最终一定是 2 吗？

 
一次加法拆成读取、加一、写回。先让 A 读取，再让 B 读取；随后交替运行，观察最终结果。

 
开启互斥锁后，线程需先获得锁，再读、加、写并释放锁。另一个线程在锁被占用时会等待。

 
缓冲区最多存放两个物品。生产者放入、消费者按顺序取出；试试空时取出和满时放入。empty 表示空位数，full 表示物品数。
每次点击把一次放入或取出视为不可分割的操作，用于理解有界缓冲区；不是实际线程或信号量实现。

 
这是可控的线程交错教学模型，展示读取、修改与写回，并非真实操作系统线程或 CPU 指令计时。






 
CHAPTER 06 / CACHE LAB
看见缓存如何工作

 
缓存按地址找到组，再比较标签。先预测，再执行；机箱中的立体缓存行会显示刚访问的组。

 
组数为 2ˢ，每组 E 行，每块 2ᵇ 字节；满组时替换最近最少使用的行。
每行格式：L 16进制地址,字节数；S 写入，M 先读后写，I 忽略。可选择跨块逐块计算，或使用官方 Cache Lab 的起始地址计数方式。

 
装入轨迹后预测第一条访问。

 
在相同缓存配置和数据上，比较逐行访问和分块访问。两个版本都会实际执行转置并验证结果。
模型采用 32 组、直接映射、32 字节块；统计的是模拟访问，不是实际 CPU 的运行时间。

 
这里展示轨迹驱动的缓存模型；官方 C 程序和 Valgrind 在 Linux 实验机运行。跨块处理方式可选择，完整实验评分仍以官方工具为准。
