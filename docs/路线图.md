# CS:APP 完整教学建设路线

> **状态说明**：本文包含早期开发记录，其中“尚未完成”的描述可能已过时；当前已交付范围、官方复验与边界以 [交付验收](交付验收.md)、[README](../README.md) 和 [官方实验机验证记录](官方实验机验证记录.md) 为准。


目标是让学生通过可视化课程学习 CS:APP 第三版的全部章节，并在可验证的运行环境中完成官方自学实验。当前项目尚未达到这一目标；各章和实验的实际状态见《CSAPP课程与实验对照》。

## 验收原则

- 每章覆盖主要知识点及其相互关系，包含讲解、可操作的可视化、练习、反馈和学习路径。用章节目录和逐项证据检查覆盖，不以示例数量代替完整课程。
- 每个官方实验以官方自学材料和说明为参照，核对任务、工具链、操作、评分及失败反馈。运行行为和评测结果需与参考环境对照；无法直接取得或分发的材料单独记录，不把原创练习称作官方实验。
- 可视化显示的状态必须来自对应的实际执行过程；教学模型与真实机器存在差异时明确说明，不能用动画通过代替实验通过。
- 实验应支持保存和恢复学生工作，并有明确的环境准备、出错提示、重置方法和回归测试。课程体验需通过键盘、不同屏幕和真实学生试用验证。
- 官方实验包含 Data、Bomb、Attack、Architecture、Cache、Performance、Shell、Malloc、Proxy；Performance 是官方列出的 Cache 的另一选项，但本项目目标覆盖两者。旧版 Buffer Lab 和 32 位 Y86 Architecture Lab 与第三版实验分别记录，不混作第三版的完成条件。

## 建设顺序

1. **真实运行基础**：验证可复现的 x86-64 Linux 环境，以及编译、调试、进程、网络和实验评测所需工具。浏览器内 Linux 当前仍处于启动排查；只有跑通程序和测试之后才能接入学生入口。与此同时保留现有教学模型，不把它当成 Linux。
2. **官方实验逐项贯通**：逐一取得适用的自学材料，建立参照运行记录，实现作业编辑、运行、检查和反馈，再将实际执行数据接入可视化。先验证一个完整实验的端到端流程，再扩展其余实验。
3. **12 章课程补全**：以官方第三版章节结构为索引拆分知识点，逐项完成讲解、交互、练习和检查；把对应实验与课程内容衔接起来。
4. **整体体验与验收**：完成学习进度和工作保存、无障碍、设备兼容、性能与故障恢复；以自动回归、参考环境对照和学生试用共同验收。

这些工作可以交错推进，但每项只在证据齐全时标记完成。教材正文、实验材料及第三方组件的使用和分发范围需逐项核查。
