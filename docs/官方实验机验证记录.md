# 官方实验机验证记录（2026-11-03）

## 环境

- macOS 宿主上的 x86-64 Debian 12 genericcloud，QEMU/UTM 用户态，1 GB 内存，串口无图形终端。
- 启动命令：`python3 experiments/native-linux/run.py --utm experiments/native-linux/assets/UTM.app --disk experiments/native-linux/assets/debian-12-genericcloud-amd64-20261026-2643.qcow2 --workspace experiments/native-linux/assets/student-workspace.qcow2`
- 自动登录 root，使用工作区 `/root/CSAPP` 中已准备的官方自学材料、GCC、GDB、Valgrind、Perl 等。
- 验证用的参考答案位于项目外 `验证参考答案（勿发布）`，仅用于证明实验机与官方评分可用，**不随产品发布**。

## 结果

### Data Lab

- 原始未完成 `bits.c`：`./driver.pl` → **0/62**（0/36 Corr + 0/26 Perf）。
- 安装参考实现后：`./driver.pl` → **62/62**（36/36 Corr + 26/26 Perf，135 total operators）。
- 说明：官方 `dlc`、`btest`、`driver.pl` 全流程可运行；参考实现通过全部 13 个函数。

### Bomb Lab

- 写入 7 行答案（6 关 + secret）后运行 `./bomb answers.txt`。
- 输出：`Phase 1 defused...`、`Curses, you've found the secret phase!`、`Wow! You've defused the secret stage!`、`Congratulations! You've defused the bomb!`。
- 说明：官方 bomb 的 6 关与 secret phase 全部拆解；不是浏览器原创六关。

### Attack Lab

- 使用参考 payload 经 `./hex2raw` 转换后提交：
  - CTARGET c1/c2/c3 → `Touch1!`、`Touch2!(0x59b997fa)`、`Touch3!("59b997fa")`。
  - RTARGET r2/r3 → `Touch2!(0x59b997fa)`、`Touch3!("59b997fa")`，并输出 `PASS` / `Valid solution`。
- 说明：官方 ctarget/rtarget、hex2raw 与评分路径可运行；5 关全部通过。



### Shell Lab

- 将参考 `funcs.c` 接入官方 `tsh.c`（保留 `parseline` 与作业辅助函数），`make` 后运行 `sdriver.pl` 的 trace01–trace16。
- 16 组 trace 均启动并完成，前台/后台、jobs、bg/fg、SIGINT、SIGTSTP、进程组与错误处理的交互 transcript 与官方 `tshref.out` 的结构一致；未出现崩溃或卡死。
- 说明：官方 `sdriver.pl` 本身只输出 transcript，不直接打印 PASS/FAIL；网页的 `check-shell` 会把学生与参考 shell 的原始输出/进程快照回传对照。本记录没有把“能运行”夸大成“自动判定 16/16 PASS”。
- 验证后已恢复官方原始 `tsh.c` 并 `make clean`。


### Architecture Lab

- Part A：参考 `sum.ys` 经 `yas`/`yis` 运行，`%rax = 0x0000000000000cba`，程序以 `HLT` 正常结束。
- Part B：参考 `iaddq-edit.py` 对 `pipe-full.hcl` 做 11 处 `IIADDQ` 扩展，`make VERSION=full` 成功构建 `psim`。
- Part C：用参考 `nc8` 函数体补全官方 `ncopy.ys` 的头部/`Done`/`End`，`make VERSION=full drivers` 后运行：
  - `./psim -t sdriver.yo` → `ISA Check Succeeds`，CPI = **1.42**（105 cycles / 74 instructions）。
  - `./psim -t ldriver.yo` → `ISA Check Succeeds`，CPI = **1.26**（466 cycles / 370 instructions）。
- 说明：这是官方 `psim` 的 ISA 检查与 CPI 输出；官方课程可能另有 driver/benchmark 评分脚本，本记录不把它等同于网页 100 分。
- 验证后已恢复 `pipe-full.hcl` 与官方 `ncopy.ys`，删除临时 `.ys`/`.yo` 并 `make clean`。

### Performance Lab

- 将参考 `opt.c` 的 `rotate_opt`/`smooth_opt` 接入官方 `kernels.c`，设置 team 后 `make`，运行 `./driver`。
- 官方 driver 输出（CPE，越小越好）：
  - Rotate：`3.4 3.6 3.4 5.2 6.6`（dim 64–1024），最佳版本平均加速 **10.3×**；基线 CPE 为 14.7–94.5。
  - Smooth：`62.5 55.2 51.6 45.9 46.5`（dim 32–512），最佳版本平均加速 **13.6×**；基线 CPE 约 695–722。
- 说明：`./driver` 的 “Summary of Your Best Scores” 是各 kernel 的加速/评分摘要，不是 100 分制；课程页面使用单独归一化的 100 分浏览器评分，官方 CPE 以 driver 为准。
- 验证后已恢复官方原始 `kernels.c`。

### Cache Lab

- `./test-csim` → **27/27**（全部 8 组参数与参考模拟器一致）。
- `./test-trans`：
  - 32×32：correctness=1，misses=**288**（阈值 <300）。
  - 64×64：correctness=1，misses=**1180**（阈值 <1300）。
  - 61×61：correctness=1，misses=**1806**（阈值 <2000）。
- 官方 Part B 得分为 8+8+10=**26/26**，Cache Lab 合计 **53/53**。
- 说明：Part A 的 csim 与 Part B 的转置均以官方测试通过；浏览器端另有对应子集检查。


### Malloc Lab

- 从官方课程镜像取得完整 11 组 trace（`amptjp`、`cccp`、`cp-decl`、`expr`、`coalescing`、`random`、`random2`、`binary`、`binary2`、`realloc`、`realloc2`），用官方 `mdriver` 跑完整套件。
- 结果：**11/11 trace 全部 valid**，总利用率 **77%**，吞吐 **534 Kops**，官方 `Perf index = 46 (util) + 36 (thru) = 82/100`。
- 环境说明：本轮完整 trace 跑在宿主的 64 位 `mdriver` 构建上；实验机内的 32 位 `mdriver` 也能编译运行，但工作区没有完整 trace（默认 `TRACEDIR` 指向 AFS）。因此不能把它写成“实验机 32 位环境 100 分”，但这是官方工具 + 官方完整 trace 的真实结果。
- 验证用分配器是开发期简单实现（不随产品发布）；实验页的浏览器分配器检查是独立子集，官方结果可通过页面导入。
- 验证后已恢复原始 `mm.c` 并 `make clean`。

### Proxy Lab

- 环境中没有 `net-tools` 的 `netstat`；为运行官方 `driver.sh`，临时用 `/proc/net/tcp` 的只读端口 shim 替代 `netstat` 的端口枚举（仅用于测试，不随产品发布）。
- 用开发期简单多线程代理（连接转发 + mutex 保护的响应缓存）运行官方 `driver.sh`：
  - Basic：**40/40**（5 个文件均 `Files are identical`）。
  - Concurrency：**15/15**（阻塞 NOP server 下仍能取到 home.html）。
  - Cache：**15/15**（源站关闭后仍能从代理缓存取到 home.html）。
  - `totalScore: 70/70`。
- 说明：代理实现是开发期验证用的简单实现，不随产品发布；官方 driver 的端口探测 shim 不影响代理转发/缓存/并发检查本身。验证后已恢复原 `proxy.c`、移除 shim 并 `make clean`。
