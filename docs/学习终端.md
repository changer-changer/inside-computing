# 学习终端

双击项目中的“打开学习实验室.command”，在打开的页面点击 3D 显示器，即可自动连接本机真实的交互式 shell。输入的命令在本机执行，文件读写会实际生效；关闭启动器窗口可停止服务。Ctrl+C 可中断前台命令。本机 Shell 使用交互式终端，可以直接使用方向键和全屏编辑器。

本机终端使用当前电脑的操作系统与 CPU，不自动提供 x86-64 Linux；因此它本身不能保证运行需要 Linux x86-64 的官方实验。服务仅绑定本机地址，终端接口需要启动时生成的随机令牌，且检查浏览器来源。

也可以使用内置学习终端。它使用浏览器内的虚拟文件系统，不会读取或修改电脑上的文件。相同浏览器和同一网址下的文件尽力保存在浏览器本地存储；清除网站数据、更换浏览器或端口后，原文件可能不可见。存储被禁用或存满时，修改仅保留在当前页面，关闭后会丢失。启动器使用固定的 `http://127.0.0.1:8765/`，方便下次继续使用。

输入 `help` 可以查看当前支持的命令。例如：

```sh
pwd
mkdir exercises
cd exercises
echo "hello world" > notes.txt
cat notes.txt
cat notes.txt | grep hello | wc -l
editor save example.ys
editor open example.ys
y86 load
y86 step
y86 regs
```

`editor save` 将右侧汇编编辑器的内容保存为虚拟文件；`editor open` 会将文件内容载入编辑器，之后需要 `y86 load` 才会编译。方向键可以浏览本次页面的命令历史。`clear` 只清除显示，不删除文件。

当前支持基本引号、管道、`>` 与 `>>`；没有变量展开、通配符、后台作业、系统进程、C 编译器、网络或真正的 Unix shell。模拟器支持的命令也可以直接输入，如 `step`；这仍然只操作 Y86-64 教学机。每个文件限 64 Ki 字符，最多 1000 个文件和目录；文件不是操作系统文件，不能用真实 shell 的实验结果替代。特别是官方 Shell Lab 需要真实的 Unix 进程、信号和作业控制，内置学习终端不支持。切换到本机 Shell 后运行的是真实系统 shell，但尚未完成官方 Shell Lab 验收。

## Linux 实验机（开发版）

在本机服务打开的页面中，可以点击“连接 Linux 实验机”，切换到真实的 x86-64 Debian shell。该入口默认不联网、不挂载宿主目录，并把文件保存在本地工作区。断开前请先保存文件并退出编辑器；页面会等待实验机完成磁盘同步后再断开。如果同步失败，连接会保留，可以稍后重试。强制退出或断电不属于这一保护范围。终端支持方向键、Ctrl+C、Ctrl+Z、Ctrl+D 和全屏编辑器；已在本机 Linux 中验证 vi 编辑和保存文件。屏幕固定为 80 列、24 行，窄屏可横向滚动。实验机的准备方法和限制见 [native-linux 说明](../experiments/native-linux/README.md)。

本机 Data Lab 的入口在课程目录中。进入实验机后，运行 `cd /root/CSAPP/datalab-handout`，阅读 `README`，使用 `vi bits.c` 修改答案，每次修改后运行 `./dlc -e bits.c`、`make btest` 和 `./btest`。在 vi 中按 `i` 开始编辑，按 `Esc` 后输入 `:wq` 并回车保存退出。请先确认终端标题是 Linux 实验机；该目录只在当前已配置的工作区中存在。

## 把 Architecture Lab 程序送入三维流水线

在此电脑的 Linux 实验机中进入 `/root/CSAPP/archlab-handout/sim/pipe`，执行 `make` 生成 `sdriver.yo`，然后执行 `/run/open3d/export-yo sdriver.yo`。页面收到文件后会显示字节数；点击“装入三维流水线”才会替换当前流水线状态，随后可逐周期观察。传输只经过本机终端，文件上限为 64 KiB。

装入的是 Y86 机器码，不会自动导入学生修改的官方 HCL；要比较同一配置，需要在三维模型中手动启用 iaddq 或调整其支持的控制规则。三维模型只支持部分 HCL，不能代表任意官方处理器修改。默认控制下，显示的模型周期包含启动时的三个周期；结束时同时显示扣除这三个周期的官方 PIPE 计数。

## 回放官方 PIPE 的轨迹

在实验机中修改官方 HCL 后，要先编译对应版本。例如，在 `sim/pipe` 目录中执行 `make -B psim VERSION=full`；修改 `ncopy.ys` 后执行 `make drivers`。随后运行 `./psim -v 2 -l 64 sdriver.yo > /tmp/pipe.trace`，再执行 `/run/open3d/export-pipe-trace /tmp/pipe.trace`。点击“回放官方轨迹”后，可用上一周期、下一周期查看该次运行的阶段、条件码和日志，最后还会显示官方报告的寄存器与内存变化。

这是对文件中已有输出的回放，页面上的 HCL 设置不会改变它。日志没有提供的状态不会由页面推断。`-l` 限制模拟器执行的指令数；如果结束状态是 AOK，运行可能因上限而提前停止。传输的轨迹上限为 256 KiB，较长运行需要降低上限或拆分；处理器名称来自日志文本。

## 把 Cache Lab 访存轨迹送入三维缓存

在 Linux 实验机的 `/root/CSAPP/cachelab-handout` 中运行 `/run/open3d/cache-transpose 32 32`。它会在新的临时目录编译并运行官方转置测试，完成后列出本次结果和轨迹路径；这样不会把旧轨迹误当成本次结果。通过正确性检查的提交函数会生成 `trace.f0`；初始代码尚未完成时，可以观察官方自带示例的 `trace.f1`。将显示的完整路径作为参数，运行 `/run/open3d/export-cache-trace 路径`，然后选择“装入三维缓存”。

页面默认选用转置评测的 `s=5、E=1、b=5`，也可改成轨迹对应的其他参数。可以预测、直接单步，或运行剩余访问；三维缓存行显示当前访问的组。官方 Cache Lab 按每条记录的起始地址计数，页面提供这一口径；另一种模式按访问实际覆盖的每个块计数，两种模式在跨块访问时可能不同。导入上限为 256 KiB、20000 条 L/S/M 记录。模型统计不能取代官方评分。

模拟 x86 环境运行 Valgrind 较慢。上述命令将官方测试程序的 120 秒等待上限调整为默认 600 秒，可在尺寸后另填 120–3600 秒；它不修改官方源码、正确性检查或缓存评分。该运行目录位于实验机的 `/tmp`，请在删除前导出需要的轨迹。直接运行原版 `test-trans` 仍保留原有 120 秒上限，并可能留下以前生成的文件。
