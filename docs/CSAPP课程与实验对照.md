## 设计边界

CS:APP 侧重从程序员视角理解真实系统，第三版的机器代码与架构实验涉及 x86-64 和 Y86-64；本项目现有 DEEP-16 是自定义 8 位数据、16 位地址的教学机。它适合展示取指、状态和部分存储概念，但不能直接执行或代表 x86-64、Y86-64、Linux 进程、真实网络或原版实验。原版动手实验需要真实或兼容的运行环境；3D 示意和原版作业应分开标记，不能以动画通过代替程序、测试和性能评测。

## 建设顺序与验收

1. 先固定课程结构、模型边界、可访问性与自动回归；每节明确目标、前置、输入输出与可重复测试。
2. 以第 2 章建立完整的位运算与 C 测试闭环；现有 3D 补码示例只是开端。
3. 引入可验证的指令执行环境，再建设第 3、4、6 章；逐条对照真实或权威参考行为。
4. 分别实现链接、OS、网络与并发模型；对真实程序实验选择合适的隔离运行方式，明确资源和浏览器限制。
5. 每个实验需要题目、可操作环境、自动检查、错误反馈、教师审阅和学生试用；同时记录尚未验证的边界。

不要宣称课程覆盖或原版实验完整，直到逐项实现并通过上述验收。

## 64 位实现的当前边界

`engine/y86-subset.js` 是独立顺序解释器，支持常见 Y86-64 指令族、64 位寄存器、条件码、内存、调用与栈，并检查非法编码和内存越界；它不是 x86-64，也不是流水线模拟器。第 4 章的 3D 寄存器是抽象示意，其值来自该解释器，不会驱动 DEEP-16。已运行基本测试，尚未与官方模拟器逐条差分验证，不能宣称完全兼容。

## 原创作业进展

新增七道 Y86-64 配套练习，并提供样例装载、单步、有限测试集检查和每次测试的指令数限制。这些练习仅覆盖第 2–4 章的部分知识点，不是 Data Lab、Architecture Lab 或其他官方实验的完整实现。详见 `课程作业与检查.md`。

## 目录与上线状态（2026-11-02）

课程目录列出 12 章，以及九项第三版常用实验的状态。可点击的相关示例只说明主题相近，不代表原版实验已经实现。旧版探索仍使用 DEEP-16；Y86-64 执行器、缓存和虚拟内存模型彼此独立，因此现阶段尚不是统一的 64 位整机。

## 汇编与缓存的统一轨迹（开发中）

汇编实验室现在使用 `System64`：Y86-64 每条指令的实际取指和数据读写会传给一个教学缓存模型，面板显示访问和命中结果。缓存使用 4 组、直接映射、每行 16 字节，按访问涉及的缓存行计数；它不影响指令的执行时序，也不模拟操作系统或真实处理器。函数调用引导基于同一执行状态，包含栈顶预测与逐条验证。其他课程模型和旧版 3D 模型仍需迁移，不能称为统一整机。

## x86-64 执行进展

项目提供原创的 AT&T 风格汇编子集，可生成 ELF64，并通过 Blink 的 WebAssembly 用户态模拟器逐条执行。浏览器中已验证算术、栈读写和正常退出，寄存器读数同步至三维画面。这一浏览器内执行器不支持完整 GNU 汇编、x86-64 C 编译或完整 Linux；另有本机开发版 Linux 实验机，见文末。执行器依赖的来源、许可及构建核查见 `vendor/x86/PROVENANCE.md`。

## 浏览器内 C 编译

C 实验室使用浏览器中的 Clang 和 wasm32-wasi 运行环境；源码与程序在浏览器内处理。可输入 C 程序与 stdin，查看输出、编译错误及退出码；程序在单独工作线程运行，并有可停止和超时机制。位运算练习先验证表达式所用语法，再编译并运行 4177 组确定性输入，覆盖有限样例而非形式证明。它不是 x86-64 Linux，不能替代官方实验所需的系统调用、并发、网络、调试与评分环境。依赖来源和许可见 `vendor/browsercc/PROVENANCE.md`。

## 原创逆向与分配器练习

逆向练习提供六个原创 x86-64 小程序，学生输入整数并逐条观察比较、跳转与退出状态；实际机器码由 Blink 执行。它不包含官方 Bomb Lab 二进制或完整调试器。

动态内存实验包括可视化的首次适配堆模型，以及独立的 C 分配器作业。后者在 wasm32-wasi 下编译并检查七项行为；这组测试不是完整正确性证明，也不测吞吐量或空间利用率。

## 官方 PIPE 回归对照（2026-11-03）

从 [Architecture Lab 官方自学材料](https://csapp.cs.cmu.edu/3e/labs.html)取得模拟器，在本机编译 `yas` 和无图形界面的 `psim`。用官方 `optest`、`jtest`、`ctest` 和 `htest` 生成的 727 个程序，对照了流水线教学模型与官方 PIPE 的结束状态、条件码、全部寄存器、内存和周期统计；全部一致。该结果针对默认 PIPE、这些生成程序和本次环境，不代表全部 Y86 程序、HCL 修改或 Architecture Lab 已完成。

官方的部分测试会在 `.yo` 中重复写入地址，因此导入器现在按文件顺序覆盖，并报告覆盖字节数。官方 PIPE 对合法指令码搭配非标准功能码的处理比项目中的顺序解释器宽松；流水线模型为匹配官方 PIPE 采用相同行为，顺序解释器仍严格检查编码。

可在本机分别取得和编译官方自学包中的 `sim` 后，用 `OPEN3D_CSAPP_SIM=/path/to/sim node tests/y86-official-ptest.test.js` 复现。测试使用临时目录生成程序，不在项目中分发官方实验材料；未设置变量时会明确跳过。官方包中的 `ctest` 将计数器预置为 8，故其自报数量包含 8 个偏差；本项目统计实际生成文件。

## iaddq 扩展（2026-11-03）

汇编器、顺序模型和可选择的扩展流水线支持 `iaddq V, rB`。基础流水线仍将它视为无效指令；切换流水线配置后需要重新装载。学生可以在三维流水线逐周期观察该指令，也可以修改部分 HCL 子集控制规则；这不是完整 HCL 或完整 Architecture Lab。

六组边界输入的编码、结束状态、条件码和结果与官方 YAS/YIS 对照一致。另用官方默认 PIPE 源码和临时加入的 iaddq 控制规则构建参考模拟器，比较官方 ptest 生成的 924 个程序；状态、条件码、寄存器、内存和统计周期一致。参考控制规则是本项目测试时加入的，不是官方提供的参考答案；这些检查也不覆盖所有程序或修改后的处理器。

已有编译后的官方 `sim` 目录时，可分别运行 `OPEN3D_CSAPP_SIM=/path/to/sim node tests/y86-iaddq-reference.test.js` 和 `OPEN3D_CSAPP_SIM=/path/to/sim python3 tests/y86-iaddq-official.test.py`。后者临时生成和编译参考 PIPE；不在项目中保存官方代码。

## 可编辑流水线控制（2026-11-03）

流水线面板新增自定义控制编辑器，支持修改取指合法性、寄存器字节与立即数读取、译码源与目的寄存器、ALU 输入、条件码更新共八条规则。学生可把 `IIADDQ` 接入这些控制路径，装入程序后逐周期观察执行、寄存器和条件码；规则保存在当前浏览器，并可恢复初始内容。

这是项目自编的 HCL 子集解释器，不调用官方 `hcl2c`。仅支持面板列出的信号，以及常量、布尔运算、相等比较、集合判断和选择表达式；当时转发、分支预测、冒险控制和其他 HCL 信号仍固定，不能导入官方完整 HCL 文件或代替官方评测；随后增加的冒险控制见下节。默认规则与官方默认 PIPE 的 727 个生成程序对照一致；在这八条规则中加入 iaddq 后，与临时构建的扩展 PIPE 对照 924 个生成程序一致。对照涉及状态、条件码、寄存器、内存和统计周期，不能推断任意自定义规则均与官方仿真一致。

可使用 `OPEN3D_CSAPP_SIM=/path/to/sim OPEN3D_PTEST_HCL=1 node tests/y86-official-ptest.test.js` 和 `OPEN3D_CSAPP_SIM=/path/to/sim OPEN3D_PTEST_HCL=1 python3 tests/y86-iaddq-official.test.py` 重跑。

### 暂停与气泡规则扩展

在原有八条规则之外，新增 `F_stall`、`D_stall`、`D_bubble`、`E_bubble` 四条可编辑控制规则，影响加载后使用、返回等待和分支预测错误后的暂停或清除。界面提供一个原创加载依赖示例，显示每周期的控制信号与寄存器。之前保存的八条规则会自动补上默认的四条，原有编辑内容得以保留。

默认规则仍与官方生成测试中的 727 个基础程序一致；扩展 iaddq 的规则与参考流水线的 924 个程序一致。另将正常控制与故意关闭暂停的控制分别编译进官方 PIPE，对照一个加载依赖程序：两种情况下寄存器与统计周期一致，关闭暂停后两者均得到错误结果。可通过 `OPEN3D_CSAPP_SIM=/path/to/sim python3 tests/y86-hazard-official.test.py` 复现。分支清除规则的修改有本项目内部测试，但尚未逐项与官方修改版对照。

这仍不是完整 HCL：转发、预测、异常处理及其余控制尚不可编辑，也不能直接装入官方完整控制文件或完成官方评测。

## 数组复制与周期练习（2026-11-03）

汇编实验室新增数组复制任务。学生编写 `ncopy` 函数后，检查器会运行长度 0–64、128、192、256，以及一组含零和整数边界值的数据；检查返回的正数个数、复制内容、目标数组两端和源数组，并限制函数长度和单次执行周期。通过后，界面给出长度 1–64 的平均 CPE 与部分长度的周期数。检查在独立工作线程执行，可停止或超时中断，并使用当前选择的流水线配置。

该练习参考官方 Architecture Lab 的目标与测量方式，但使用项目自建驱动和确定性输入；它不是官方评测或评分，也不能证明所有输入正确。获取官方自学包后，可在编辑器中输入自己的函数代码。用包中的基准函数和本项目 69 组驱动，对照官方 YAS 与默认 PIPE，程序编码、返回计数和周期统计一致；这不代表其他函数和处理器修改已全面验证。可用 `OPEN3D_CSAPP_SIM=/path/to/sim node tests/architecture-copy-official.test.js` 重跑。官方完整 HCL、实验流程和评分仍待实现。

数组复制练习还可装入四元素的逐周期三维视图：源、目标数组的数值来自同一个流水线模型的内存，颜色由该周期的实际读写事件驱动。模型还提供文字状态，停止时对照复制结果和正数计数。这个视图展示的是 Y86 教学模型，不是实际硬件，也不替代官方评分。

### 官方机器码到三维流水线

实验机提供 `/run/open3d/export-yo`，可将学生选定的 `.yo` 通过本机终端发送到页面。页面先校验大小和格式，再由学生选择是否装入，不会直接覆盖当前流水线状态。使用官方 `sdriver.yo` 做端到端验证：页面运行至 HLT 时，寄存器与官方 `psim -t` 输出一致；页面模型为 76 个周期，对应官方 PIPE 统计的 73 个周期。该验证只覆盖这个程序及默认控制配置，不代表全部实验或自定义 HCL 已联动。

### 官方 PIPE 轨迹回放

在本机实验机中编译选定的 HCL 后，学生可将 `psim -v 2` 输出发送至页面，逐周期回放官方日志中的阶段状态、条件码和事件，并查看运行结束时报告的寄存器及内存变化。页面明确区分官方轨迹与自建流水线模型；没有从日志缺失的字段推断状态。单个轨迹限 256 KiB，指令上限可能使运行提前停止。

本次用同一条加载后使用程序对照官方 `pipe-std.hcl` 与官方提供的 `pipe-broken.hcl`：标准版本的 `%rdx` 为 42，而 broken 版本的 `%rdx` 保持初值；两份轨迹均在页面回放并显示各自的 HCL 名称和官方结果。这验证了这两份轨迹的传输与展示，不代表所有 HCL、所有程序或整门课程已验收。

### 官方 Cache Lab 轨迹到三维缓存

Linux 实验机可将官方 `test-trans` 生成的过滤后轨迹发送至页面。页面可按官方 Cache Lab 的起始地址口径模拟，也可按跨块访问逐块模拟；支持单步、预测和运行剩余访问。

在本次 32×32 官方自带转置示例中，Valgrind 生成 2053 条访问；页面使用 `s=5、E=1、b=5` 时得到命中 869、未命中 1184、替换 1152，与同一文件上的官方 `csim-ref` 一致。另用跨块短轨迹检查了起始地址口径，双方均为命中 2、未命中 1、替换 0。两项对照不证明任意轨迹或完整 Cache Lab 已验收。

### 64×64 轨迹与模拟环境超时

在本机模拟的 x86 Linux 中，原版 `test-trans` 的 120 秒等待上限曾在 64×64 示例上超时；失败后原目录仍可能留有旧的 `trace.f1`，不能将其作为本次结果。现提供 `/run/open3d/cache-transpose`：每次在新目录编译并运行官方测试，只将该测试的等待上限默认延长至 600 秒，并记录源码摘要与本次结果，不修改官方源码和评分计算。

使用该入口后，官方自带的 64×64 示例生成了 8197 条记录；`csim-ref` 和页面缓存模型均得到命中 3473、未命中 4724、替换 4692。实验仍在模拟器内执行，实际等待时间取决于设备；官方作业的其他输入、学生实现和完整课程尚未完成验收。

### 官方 SEQ 取指时状态（2026-11-03）

运行 `/run/open3d/capture-seq ./ssim 程序.yo 32` 后，工具使用同一官方模拟器从头多次运行，核对各次取指序列及最终状态，再把每一步的官方状态变化送往页面。上限为 64 条，页面展示相对初始状态变化的寄存器、内存和条件码；三维卡片只展示其中部分内容。

官方 SEQ 在每一步开始时写回上一条指令，所以第 n 条取指对应的是当前指令写回前的状态，不是执行完成后的状态。本机用官方 `asumi` 检查：第 1 条取指时寄存器没有变化；第 3 条取指时 `%rsp=0xf8`、内存 `0xf8=0x13`，与官方运行到相同步数的输出一致。这里只验证了该程序及默认处理器，未覆盖所有学生修改或所有程序。

### Shell Lab 实际进程采样（2026-11-03）

官方单项测试运行时采集驱动及子孙进程的 `/proc` 快照；页面可切换参考和学生运行，逐个查看 PID、父进程、进程组与内核状态。三维卡片显示每个采样中最多四个进程，完整采样仍以文字列出。目标采样间隔 0.15 秒，实际受负载影响，仅保存状态变化，最多 80 个采样；采样可能改变调度，且不能证明未采到的进程或状态不存在。

本机 trace08 参考运行中，采样显示驱动、参考 shell 和两个 myspin 子进程；两名子进程的 PID 与同次参考输出一致，且属于不同进程组。另观察到参考 shell 的僵尸状态；本次没有采到 stopped 状态。该验证只覆盖这次运行，并不代表全部信号、作业状态或全部测试已完整追踪。

### 进程采样改进（2026-11-03）

采样器改为沿 `/proc` 中的父子关系读取测试进程树，并记录采样次数和最大观察间隔；界面同时说明各进程并非原子读取。相同实验环境中各运行一次 trace08，旧的全量扫描采样 39 次、最大间隔 0.117 秒；新方法采样 47 次、最大间隔 0.106 秒。两次目标间隔均为 0.08 秒，参考输出除进程号外一致，且均未采到停止状态。这只是各一次的运行记录，不代表稳定性能提升或信号覆盖率。

页面端另一次运行中，参考输出的两个子进程 PID 与采样一致，页面显示最大观察间隔 0.116 秒。短暂状态仍可能遗漏，采样本身也会影响程序运行。

### 虚拟内存：TLB、缺页与脏页（2026-11-03）

第 9 章新增独立分页模型：页大小 16 字节、4 个页框、2 项全相联 LRU TLB，页框按 FIFO 置换。可以访问自定义地址、读取或写入字节；模型区分未分配、已分配但未驻留及只读保护。可处理的缺页需要先装入页面，再显式重试；换出脏页会写回，且若 TLB 中有旧映射则将其清除。

已在桌面与 390×844 页面验证 TLB 未命中和命中、缺页装入、无效地址及脏页换出后重新读取 99；测试还覆盖只读保护、TLB LRU 和 2000 次确定性读写。此模型用于解释机制，不执行 Linux 的页表、实际磁盘 I/O 或完整操作系统策略。

### binary32 浮点位表示（2026-11-03）

第 2 章新增单精度表示实验：可以输入十六进制位模式或十进制数、逐位修改，并查看符号、指数、小数字段及其解释。覆盖正负零、非规格化数、规格化数、无穷大和 NaN；十进制输入使用最近值舍入、平局取偶。三维字段是表示模型，不会改变实验机内存。

测试覆盖边界与 10000 个位模式；2007 组十进制输入与本机 C `strtof` 的结果一致。已在桌面和 390×844 视口检查交互、字段位置和练习反馈。这些结果不证明所有输入或所有设备均无误，也不代表第 2 章及官方 Data Lab 已完整。
