# 部署

## 静态服务器（推荐用于课程页）

项目没有构建步骤。把整个仓库放到任意静态 HTTP 服务器即可：

```sh
python3 -m http.server 8000
# 或 nginx / Caddy / GitHub Pages
```

要求：

- 以项目根目录为站点根；`index.html`、`course/`、`labs/`、`vendor/` 的相对路径必须保持。
- 通过 HTTP(S) 访问，不要用 `file://`。
- 不要把 `server/local_terminal.py` 暴露到公网；它只用于本机终端桥。

## GitHub Pages

仓库包含可手动触发的 `.github/workflows/pages.yml`：

1. 仓库 Settings → Pages → Source 选择 **GitHub Actions**。
2. Actions → `deploy-static-site` → Run workflow。
3. 部署后访问 Pages URL；课程、实验页与浏览器 C 工作台应可用。

注意：

- GitHub Pages 不支持本项目可选的 Linux VM 终端；需要 VM 的官方实验请在本地启动。
- `vendor/` 约 100+ MiB，Pages artifact 会较大；如果超出你的套餐/构建限制，改用普通静态主机或把大运行时放到 Releases。
- 仓库默认不包含官方实验包/VM 镜像，Pages 上也不会凭空出现这些功能。
- 某些浏览器/企业策略会对 WebAssembly/Worker 有限制；以实际访问日志和控制台为准，不要假定 Pages 上所有实验都与本地一致。

## 自定义域名/子路径

项目使用相对路径（`../course/...`、`./vendor/...`），一般可放在子路径。若用反向代理改写路径，请确保：

- `course/`、`labs/`、`vendor/` 与根 `index.html` 的相对关系不变；
- Worker 脚本与 wasm 的 MIME 类型正确（`.wasm` 为 `application/wasm`）；
- 不要缓存 `index.html` 过久，避免课程更新后仍加载旧资源。

## 隐私与日志

静态主机可能记录访问日志。项目本身没有账号、遥测或上传；学习进度只在浏览器 `localStorage`。如果部署到学校平台，请在隐私说明中写清主机日志与 localStorage 的使用。
